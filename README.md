# 文献伴读

一个面向 **MinerU 解析结果**的 Windows 论文阅读器：把原文、解析后的内容、笔记和 AI 讨论放在同一处。

## 解决什么问题

读论文时，PDF、提取出的文字、公式图片、笔记和 AI 对话常散落在不同窗口。这个工具面向已经用 MinerU 解析论文、希望对照原文精读并持续整理个人论文库的读者。

## 能做什么

- 扫描论文库，阅读 MinerU 生成的 Markdown，并与原始 PDF 对照；也可通过界面的“导入论文 PDF”批量加入尚未解析的论文，每篇单独建立目录并直接阅读 PDF。
- 按论文保存整篇笔记；对 MinerU Markdown 的原文选区可添加批注和 AI 翻译。用标题、标签、收藏和最近阅读整理文献。搜索可读取 MinerU 解析出的论文标题，支持部分词和少量拼写误差。
- 在当前论文旁与 Codex 对话，可发送选中文字或图片。每篇论文关联独立对话，重开后可接续阅读。

## 特点

- **围绕原文阅读：** PDF、解析内容、批注和对话同屏，方便核对 AI 回答。
- **保留个人阅读脉络：** 批注关联原文，论文与对话、阅读布局分别保存。
- **本机管理论文库：** 阅读记录存于本机；程序不会主动修改原始 PDF、Markdown 或图片。AI 功能通过本机 Codex CLI 连接服务，使用 AI 时相关内容会按请求发送给服务处理。

## 运行

需要 Windows 10/11、.NET Framework 4.x。论文库可包含 MinerU 解析目录（`markdown.md` 和原始 PDF），也可包含仅有 PDF 的独立论文目录。使用 AI 功能还需安装并登录 [Codex CLI](https://developers.openai.com/codex/cli)；程序通过本机 `codex app-server` 连接，无需在阅读器中填写 API Key。

在 PowerShell 中进入本项目目录：

```powershell
.\Build.ps1
..\文献伴读.exe
```

首次打开时选择论文库根目录。阅读记录默认位于可执行文件旁的 `state/ai-literature-reader/`。可把现有 MinerU 解析结果关联为正文论文的支撑材料，也可把视频、PDF、ZIP 和数据文件复制到程序旁的独立 `attachments/` 目录并关联。左侧展开论文可查看附件；视频和 ZIP 内的常见视频可在阅读器中播放。论文库会标记 PDF 内容完全相同的副本，删除重复目录需要手动确认。

“导入论文 PDF”支持多选，会将每份 PDF **复制**到论文库内新建的同名目录，并保存为 `source.pdf`；原文件不移动。新目录暂时没有 Markdown 时默认使用浏览器内置阅读器显示 PDF，整篇笔记、标签和 AI 对话可用。以后在同一目录加入 `markdown.md` 即可切换到原有对照阅读。文字批注和 AI 翻译仍针对 Markdown 选区；PDF 阅读区不绘制批注。重复目录的自动删除仅用于已有 MinerU 论文。

文件导入有两个入口：把已下载的 PDF 拖到左侧论文库、顶部或页面空白区域，会直接后台导入，无需确认或先加入清单；拖入不自动打开清单，也不切换正在阅读的论文。点击“导入论文 PDF”则打开可收起的待选清单，支持反复从不同文件夹选取多份文件；每次选择都会追加，标记选取批次，可移除个别项目，点击“开始导入”才执行。清单仅在本次页面中保留，关闭/刷新会丢失未导入选择；当前文件只保留浏览器 File 引用，不提前复制。后台导入时仍可追加下一批，任务串行处理；已成功项目不会因再次点击开始而重复提交，失败项目可重试。同名文件分别保留，新目录自动添加序号，不以文件名猜测内容重复。支持单份 8 GB 以内 PDF，不递归拖入文件夹；原文件不移动。导入后显示“最新加入”，保留当前阅读内容。正在导入或存在待选文件时，离开页面会由浏览器提醒。AI 对话区域的文件拖放继续交由原有对话处理。PDF 内置 iframe 可能拦截直接拖放，建议投放到左侧论文库或页面控件区域。

左侧“最新加入”按入库时间从新到旧平铺显示论文，可继续使用搜索和阅读状态筛选，不受目录层级限制；每行显示入库时间和原目录。“最近阅读”仍按打开时间排序。新导入记录完成时刻，旧论文以目录创建时间估计，带“约”标记；估计值首次扫描后独立固定在 `state/ai-literature-reader/paper-added/`，不修改旧笔记、批注及其保存路径，后续写笔记和改标签不影响入库顺序。同步时可一起同步此索引目录。导出阅读资料会只读已有索引，在副本生成“入库信息.json”和对应清单字段，不触发初始化。

整篇论文笔记默认显示排版后的阅读视图，可切换编辑，使用标题、加粗、斜体、列表、引用及待办工具（Ctrl+B / Ctrl+I，Ctrl+S 立即保存）。仍然自动保存到原有 `review.note`，旧笔记不迁移、不重写。可选“小结模板”只在文末补充尚未存在的六个标题，不覆盖内容，也不要求填满；阅读视图中的二级标题可折叠。笔记栏顶部的“并排展开”在原有网格中增加右侧宽度，论文和笔记分别滚动，不另开窗口或遮挡正文；拖动左边界调宽，收回后恢复普通侧栏宽度。空间不足时临时收起 AI 或目录，收回后恢复；用户主动调整的开关优先。普通宽度和展开宽度分别记忆，既有文字批注保持可用。纯 PDF 同样支持整篇笔记。

Markdown 文字批注（含 AI 翻译）的“加入笔记”会插入原文、评论/译文及返回批注的链接；选中 Markdown 中的本地图片后，可在正文上方点击“图片加入笔记”。编辑模式下插入到当前光标处（不替换选中文字），阅读模式下追加到文末；同一来源链接仍存在时避免重复加入。摘录是独立快照，不随原批注后续修改或删除而变化；批注被删后会提示无法定位，摘录仍保留。图片以相对路径引用原论文目录文件，不复制图片，不保存运行端口；阅读预览可显示图片并返回 Markdown 原图。只加载当前论文目录内的本地图片，路径仍由现有资源接口校验；原图丢失会显示提示。此功能不包含 PDF 截图或批注。

“批注”和已有批注的“修改”使用右侧批注栏内的编辑卡片，不再弹出模态窗口。进入编辑时固定原文及定位信息，之后继续选字、复制、滚动不改变这条批注的来源；可用“定位原文”返回。点击保存或 Ctrl+Enter 才写入正式批注；空白时取消/关闭直接生效，有改动时确认放弃，Escape 仅在编辑卡片内部执行取消。本次运行中，每篇论文暂存一份草稿，收起侧栏或切换论文不丢失，返回论文恢复；新建另一条或编辑不同批注时会先确认是否放弃当前有改动的草稿。草稿不写入正式记录，关闭程序后不保留。标题与标签窗口保持原样。

笔记栏顶部可一键切换“均衡 / 笔记优先 / 批注优先”，调整上下空间，无需拖动，内容和各自滚动位置保留。默认均衡，手动选择记在当前电脑上；进入批注编辑会临时切到批注优先，不覆盖手动偏好。与“并排展开”的左右宽度调节相互独立。纯 PDF 且没有文字批注时隐藏这组切换，空间全部用于整篇笔记。

跨电脑同步时，可同步论文库、`attachments/` 与 `state/ai-literature-reader/papers/`；各电脑保留各自的 `settings.json`。附件关联改为 `attachments/_links/` 中每条关联一个 JSON，首次使用新版本会从旧 `state/ai-literature-reader/attachments.json` 迁移，旧文件保留且不再更新。删除关联会留下删除记录，避免旧清单在另一台电脑上恢复已删附件。所有同步电脑都应更新到新版本；旧版程序无法读取新建的逐条附件记录。论文库内部目录结构需一致，避免同时在两台电脑上编辑同一篇论文的记录。旧版按绝对路径保存的论文记录会在本机扫描时复制为新格式，旧文件保留。

## LaTeX 引用

打开论文后，点击顶部“引用”。引用窗口按当前信息、手动查询、复制与导出、批量导出分区；状态条显示读取、识别、待确认和保存结果。引用命令预览、批量导出格式和勾选计数即时联动，展开批量导出时自动读取已保存文献。动效遵循系统减少动画设置。窗口可按住标题栏拖动，双击标题栏回到中央；引用浮窗打开时也能操作后面的 PDF。只有 PDF、以及 PDF 加 MinerU Markdown 的论文均可使用，不要求先解析全文。

- 打开“引用”窗口后，尚未保存书目信息的论文会自动启动识别；已有记录直接显示，不重复查询或覆盖。关闭窗口后重新打开可重试自动识别，手动查询始终保留。
- 自动识别会从 PDF/MinerU 内容提取线索、查询编号或标题、比对标题与作者；标题规范化后一致、作者在首页信息中吻合、年份无明确冲突且没有接近的不同候选时，自动保存。作者旁的单位编号会在比对时忽略；单独一个 DOI、搜索第一名或标题相似并不足以自动保存。
- 手动查询时始终显示“当前已保存的结果”。查询或选用候选仅更新待保存内容；“选回已保存结果”可以放弃未保存的替换。覆盖保存时只保留上一版（包括引用键），可用“撤销上次覆盖保存”恢复，重启后仍有效；相同内容再次保存、复制或导出不会冲掉上一版。每次新的覆盖替换上一版，撤销后不保留重做历史。
- 不确定时自动展开“手动查询或修正”，展示候选供选择后保存；没有可靠结果时提示补充标题、编号或导入 BibTeX。手动查询功能保留。
- 已保存的记录直接用于复制/导出，不再反复识别；一键识别不会覆盖已有记录或改变已有引用键。需要纠正时使用手动查询或编辑后保存。自动建立的新记录会避开已占用的引用键。
- arXiv 线索存在时保留预印本身份，并核对指定版本，不自动改成同标题的正式发表版本。
- 输入框支持 DOI、arXiv 新旧编号、带版本号的编号及对应文章链接。arXiv 使用官方 API 获取标题、作者、年份，生成预印本条目并保留版本号；正式发表信息只作为说明，不自动把预印本替换成正式版。
- 没有 DOI 时，可输入/修正标题，选择 Crossref（期刊、会议等）、arXiv 或两个来源检索。手动搜索显示至多每来源 5 条结果，按标题词语相似程度排序，不自动确认；点击“选用此条”后仍需核对保存。某个来源不可用时提示原因，保留其他来源的结果。
- 也可输入 DOI 或 doi.org 链接联网获取 BibTeX，或导入/粘贴单条 `.bib` 文献。可以直接编辑文献数据；暂不支持自定义 BibTeX 宏、字符串拼接、批量 `.bib` 导入和 OCR。
- 保存后可一键复制 `\cite{引用键}`，也可选择 natbib 或 biblatex 对应的引用命令。新识别文献的引用键采用“第一作者姓＋年份＋标题关键词”；短的冒号前标题优先作为论文名称，否则取前三个非停用词，重名自动追加 a、b 等后缀。缺少作者或年份时使用 Anon、Nd。元数据更新保留已保存的引用键；手动指定的重名引用键会被拒绝。导入 `.bib` 文件时保留文件中原有引用键。修改已用于正文的键时，需要同时修改正文。
- 导出当前文献，或展开底部文献列表，点击“读取已保存文献”，使用“按标签选择”自动勾选该标签下所有已保存条目，再导出 `references.bib`。也可全选当前列表、取消全选或取消个别条目。标签使用论文现有标签，修改/重命名标签后重新读取即可，无需重新识别。仅包含已保存书目信息的论文；标签下尚未识别的论文需先识别保存。导出提供 BibTeX 与 BibLaTeX 的常用字段适配；复杂条目仍需按投稿模板核对。导出文件由用户手动放入 LaTeX 项目或上传 Overleaf，不自动修改已有 `.bib` 文件。
- 文献样式由 LaTeX 模板决定。例如传统 BibTeX 模板使用 `\bibliographystyle{plain}` 和 `\bibliography{references}`；BibLaTeX 模板使用 `\addbibresource{references.bib}`、`\printbibliography`，并用 Biber 编译。已有期刊/学校模板优先遵照其说明，不混用配置。
- 窗口最下面的“复制参考文献到 Word”按需展开，可选择当前已保存文献，或使用上方批量列表的勾选（含标签筛选）。内置国标 GB/T 7714—2015 顺序编码与著者—出版年、APA 7、IEEE、Nature、Science 六种 CSL 样式，离线排版并预览，支持复制 HTML 富文本及保存 Word 可打开的 HTML。粘贴时选择“保留源格式”；这是普通文末列表，不关联 Word 正文引用或自动维护编号。顺序由样式决定，无排序规则时沿用列表顺序。支持导入含 bibliography 的中英文 CSL 独立样式，保留最近一种及所选样式于浏览器本地存储；其他语言会提示术语回退。切换样式不改变书目记录，复制也不自动保存当前编辑。缺少作者或年份会提示核对。

PDF 提取使用 `pdftotext.exe`，依次从程序旁 `tools/`、系统 PATH、`C:\texlive\年份\bin\windows` 查找。本机已有 TeX Live 可直接使用；在另一台电脑上需安装该工具或提供完整依赖，程序不捆绑它。缺少提取工具时，手动 DOI 查询和 BibTeX 导入仍可用。扫描件暂不能自动提取。编号查询会把 DOI 发给 doi.org 及其注册机构，或把 arXiv 编号发给 arXiv 官方 API；标题检索把输入/提取的标题发给选中的 Crossref/arXiv 服务。不上传 PDF 或 Markdown。新增检索请求串行执行并间隔至少 3 秒，成功结果保留在本次运行的内存缓存中。

联网检索覆盖范围取决于 Crossref/arXiv 收录情况，不能保证找到所有论文；扫描件、标题提取错误、数据库未收录时，可手动改标题重试，或使用 BibTeX 导入/编辑。实现参考 [Zotero PDF 元数据识别](https://www.zotero.org/support/retrieve_pdf_metadata)、[JabRef PDF 导入](https://docs.jabref.org/collect/findunlinkedfiles)、[Crossref API](https://github.com/CrossRef/rest-api-doc) 和 [arXiv API](https://info.arxiv.org/help/api/user-manual.html)，未复制其源码。

书目信息单独保存在 `state/ai-literature-reader/citations/`，不修改原始 PDF、Markdown 或阅读笔记。跨电脑同步时也请同步此目录。记录按当前论文相对目录关联，移动/重命名论文目录后需要重新关联文献信息。

## 导出阅读资料

论文库左下角“导出阅读资料”提供独立选择列表：按标签追加勾选，可组合多个标签，也可搜索标题、目录或标签后手动增减，搜索不清空已有选择。选择资料包名称和目标位置后，程序始终新建带时间及随机后缀的目录，不会覆盖已有目录，也不允许导出到当前论文库、阅读记录或附件目录内。对话框显示进度、完整目标路径和资源说明，完成后可打开目录，在外部 Codex 中将其作为工作区。

自动资料包名称会组合依次追加的标签；手动输入非空名称后不再自动覆盖，清空名称可恢复自动命名。清空勾选会清除自动名称中的标签。目录选择使用 Windows Common Item Dialog（文件夹模式），在单独 STA 线程按次创建并释放，使用调用时的前台窗口作为所有者，显示后前置，并仅为该线程启用高 DPI 适配。刷新或重新开始导出会隔离上一轮进度请求；打开导出目录复用资源管理器查找和前置逻辑。

资料包包含文献清单、说明、manifest.json、已有 references.bib，以及每篇论文的 PDF、可用 Markdown、被文本引用的本地图片/支持的资源、阅读笔记、批注和 AI 翻译、原文摘录与前后文、原始阅读记录快照及已有引用记录。复制资源放到各篇独立的“资源”目录，改写常用 Markdown 内联/引用式链接和 HTML src/href；代码围栏及行内代码不改写。应用内批注链接转为摘录编号锚点，图片链接转为副本资源地址。不在所属论文目录内、缺失、不支持、网络资源及复杂 srcset 等不能完整转换的情况列入“导出说明与缺失资源.md”；不会自动下载网络文件、识别 DOI 或对 PDF 做 OCR。PDF-only 论文保留 PDF 并明确标识缺少 Markdown，不把用户笔记冒充正文。SVG 等自带资源引用需要核对。精确跳转依赖外部 Markdown 阅读器，编号、原文摘录和上下文独立保留。

**导出独立且只读原资料。** `MaterialExport.cs` 使用自己的阅读记录读取逻辑，既不调用会更新打开时间的 GetPaper，也不调用可能迁移旧记录的 LoadReview；不修改原论文、批注、路径、引用键、配置或关联方式。当前打开论文的阅读记录可通过窗口内快照带入，导出本身不触发保存。所有创建/转换只发生在新建输出目录；失败时保留“导出未完成.txt”和失败说明，不覆盖旧资料、不递归清理原目录。符号链接/目录联接不跟随，资源按实际路径检查所属范围。整个导出目录可移动，内部相对链接保持有效；单独改名内部文件需自行同步链接。

不自动导出未保存的局部批注草稿、AI 聊天历史、账户设置、视频、ZIP 或未选择的关联支撑材料。此功能提供阅读资料快照，不能直接当作应用备份导入恢复。导出结果的详细结构和排除项见资料包内“资料说明.md”。

## PDF 导入、重复检查与回收站

拖入 PDF 会直接复制入库；“导入论文 PDF”支持多次跨文件夹选取，累计后批量导入。原文件保留，同名目录自动避让。重复检查覆盖 PDF-only 和带 Markdown 的论文，以 PDF 文件内容的 SHA-256 为准；不同版本或不同文件内容不会仅因同名而认定重复。导入后如发现重复组，会提示查看重复论文。

标题栏直接提供“移至回收站”；重复列表中的副本也可直接使用同一确认窗口，无需先打开论文。确认窗口显示实际目录、阅读记录和待保留副本。通过 Windows IFileOperation 显式请求回收，进度回调拒绝永久删除；失败或取消时不会退回永久删除。目录联接、符号链接、嵌套论文和仍被其他论文使用的解析附件会阻止操作。独立的阅读记录、书目记录、附件文件及关联记录保留；从系统回收站还原到原位置后可重新关联。回收父论文后，其仍存在的解析材料重新显示在库中。旧的永久删除重复目录接口保留兼容，当前界面不再调用。

## 换电脑迁移

关闭程序后，将 EXE 同目录下的 `文献伴读.exe`、`论文/`（或实际选用的论文库）、`state/` 和 `attachments/` 一起复制，并保持它们的相对摆放关系。`state/` 包含笔记、批注、标签、收藏、阅读状态、引用键、书目信息和加入时间等，不可只复制 EXE。`attachments/` 包含附件副本和 `_links/` 关联记录，也须完整复制。源代码目录只用于开发和重新构建，日常运行不需要。

新电脑上若绝对路径不同，启动后重新选择复制后的论文库根目录；论文库内部各篇论文的相对目录保持不变，不要逐篇改名或重排。现代阅读记录和引用按相对目录匹配。旧版尚未迁移的绝对路径记录，以及 Codex 对话绑定，不保证随根目录变化自动匹配。Codex CLI、登录与聊天历史由外部 Codex 环境管理，复制应用的四项资料并不迁移其完整环境。浏览器本地保存的自定义 Word 样式和界面偏好也不在这份文件备份内。

PDF 文字提取还需要新电脑上可用的 `pdftotext`（见上文）；若另行配置了程序旁的 `tools/`，也一并复制完整工具及其依赖。内置网页资源已嵌入 EXE，不需要单独复制源码中的 assets。GitHub 仓库保存源码，不包含个人论文、阅读数据、附件和编译后的 EXE，不能代替个人资料备份。
